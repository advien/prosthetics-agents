Multi-agent architecture · sequence B → C → A

Prosthetics agent blueprints

Block diagrams for the three-stage project: a clinical fitting assistant (B), a fabrication-pipeline orchestrator (C), and a real-time prosthetic control loop (A) — three separate multi-agent systems that share one message-logging spine.

working schematics — revised as scope changes, redrawn as a single figure at project completion

overview

How the three projects relate

B and C are one continuous pipeline — a device recommendation from B becomes the input spec for C. A runs on a different timescale with different data (sensor ticks, not patient records) and stays a separate module. All three write to the same event log, which is what actually makes this "one project" rather than three unrelated demos.

stage B

Clinical fitting assistant

A patient-record object is threaded through four agents. The recommendation never reaches documentation directly — it must clear a review agent first, which can escalate to a clinician instead of passing it on.

Intake Agent
turns free-text history into a structured patient profile — amputation level, K-level activity, lifestyle, comorbidities.
Biomechanical Analysis
derives load, range-of-motion and gait requirements from the profile.
Recommendation Agent
matches requirements against a component catalog and drafts a device recommendation; reapplies the safety agent's required changes on revision.
Safety / Review Agent
deterministically checks component ratings and red flags; approves, sends back for revision (bounded, default 2 attempts), or escalates to the clinical team.
Documentation Agent
always writes the clinical document — adds an escalation note and states no fitting proceeds when the gate escalated.
stage C

Fabrication orchestrator

Picks up where B's recommendation ends and carries it to a production-ready file. The QA agent can reject geometry and send it back upstream — the loop over the top of the diagram is the mechanism that matters here, not the straight-line pipeline.

Scan Processing
cleans the raw 3D scan of the residual limb and extracts landmarks (via mesh processing).
CAD Generation
parametrically builds socket/component geometry from landmarks and the device spec.
Manufacturing Scheduling
plans print/mill steps and toolpaths for the generated geometry.
QA Agent
checks geometric tolerances; fails bad geometry back to CAD generation instead of passing it downstream.
stage A

Real-time prosthetic control

Two loops at two speeds: a per-tick control path where the safety supervisor sits directly on the command line, and a per-session adaptation loop that retunes intent recognition offline from logged outcomes.

Sensor-Fusion
combines synthetic EMG/IMU streams into a single state estimate.
Intent-Recognition
maps the state estimate to a candidate motion intent.
Motion-Planning
turns intent into an actuator command trajectory.
Safety-Supervisor
validates every command before it reaches the actuator; substitutes a safe-hold command on failure.
Adaptation Agent
reviews session logs offline and updates the intent model between sessions, not within one.
